# Crypto Sniper — exit and cost research (2026-11-05)

**Status: RESEARCH ONLY. No strategy update is approved.**

Scope: only the Crypto Sniper project. This branch does not modify the
production LONG/SHORT candidate, stop-loss, TP1/TP2 or score rules, and
never calls authenticated Bitget endpoints or places orders.

## Historical evidence available before this integration

Earlier comparison reconstructed the live Crypto Sniper signal rules on 17
archived Bitget USDT perpetual crypto markets. Non-crypto tokenized equity
symbols ANTHROPICUSDT, SAMSUNGUSDT and NBISUSDT were excluded.

- March 1–June 30, 2026 training and July 1–November 3, 2026 evaluation.
- Reference default: TP1 1.5R/TP2 2.5R, 50% partial at TP1, 24h holding cap.
- Next completed 15m signal -> next 15m open entry; stop-first on ambiguous
  OHLC, unfavorable fill on gaps, no overlapping position per market.
- Illustrative round-trip cost: 0.12% notional; actual per-market funding was
  not collected. Net R is a pooled sum, **not portfolio return**.
- July–November was already evaluated in the previous four-bot comparison.
  It is **not a new untouched out-of-sample holdout**.

## New implementation

- backtesting/exit_policy.py: immutable policy definitions, conservative
  stop-first OHLC fill logic, fee/slippage cost expressed in R, optional
  funding scenario (not historical funding), breakeven only on later bars,
  and explicit censoring when the backtest ends mid-position.
- backtesting/exit_study.py: invokes Crypto Sniper's existing backtesting
  signal engine; consumes a downloaded local Bitget CSV archive or extracted
  folder; tests all eight predeclared policies at 0.12% and 0.18% round-trip
  costs; generates trade-level CSV, aggregate summary and decision.json.
- tests/test_exit_policy.py: deterministic safety/regression tests for
  stop-first, stop gaps, both directions, partial TP and cost calculations.

From repository root, after supplying a verified OHLCV download:

    python -m backtesting.exit_study --archive bitget-batch-0.zip --out-dir exit_study_results

Or use a folder:

    python -m backtesting.exit_study --data-dir data --out-dir exit_study_results

Input format: data/SYMBOL/15m.csv, 1h.csv, 4h.csv and 1d.csv,
each with timestamp, open, high, low, close and volume.

**No archive is committed to this repository.** Default dates reproduce the
previously inspected March–November comparison window. Use explicit date flags
for fresh data, and maintain a verifiable out-of-sample research log.

## Approval gate

A hypothetical rule must first clear at least 50 trades, profit factor >= 1.30
and net expectancy >= +0.15R in the training data, with sensible maximum
drawdown and 0.18% cost stress. These are research screening guidelines, not
proof of profitability.

Actual approval additionally requires newly untouched data, sequential
walk-forward checks, historical funding, realistic manual execution assumptions,
portfolio/correlation risk assessment, and forward paper-trading validation.
The exit-study command **always records production_strategy_change_approved=false**
for these previously viewed samples; it does not modify or deploy a live strategy.

Secrets must not be checked in. GitHub Actions code tests are not a profitability
certificate. A&T TrendHive bots remain signals-only and manual-execution-only.
